# Studio — Stage 3 plan: Reels montage

File: `docs/studio/2026-09-29-stage-3-plan.md`.

Status: final for dispatch. It folds in:
- the owner's answers of 2026-09-29, including the V1–V4 defaults, all accepted;
- the critic review (the plan critique's findings A1–A5, S1–S20, the nits and cuts);
- the critic's v2 verification: B1, B2, C and its backlog items 1–11, all applied;
- the owner's decisions of 2026-09-29, made after the plan was first committed: one video
  file, the caps accepted, «Новый монтаж» (see the decision log).

No owner question is open.

Goal: turn an avatar's generated scene photos, and the owner's own uploads, into a finished
Instagram Reel (a 9:16 MP4) in a timeline editor. It should feel "roughly like Canva's video
editor, not as complex as CapCut". The same result must be reachable with no UI at all: every
montage is a data record (`MontageSpec`), and the engine renders it headless. Stage 4's
autopilot will generate those records and render them in bulk.

## Slices

Each slice can be released on its own. What a slice has not built stays unreachable. Until
its slice lands, the engine refuses any spec part that needs it, with `MONTAGE_INVALID` "not
yet supported"; it never drops that part silently (N9). The UI controls for it stay disabled,
titled «Скоро».

- **3a — the render core, headless.**
  - The `MontageSpec` timeline contract.
  - The eligibility rule, the derived "used" index and the reject marks.
  - Shared geometry and timing, and focus resolution.
  - The two-pass graph builder, the render queue and runner, the output verifier, video
    records.
  - A packaged headless E2E.
  - Photo and collage clips only.
- **3b — the media protocol, text and stickers.**
  - All `studio-media://` routes with Range support.
  - Fonts plus an emoji font, the caption rules, and text layout and rasterising owned by the
    engine.
  - A generated sticker set, and layers in the graph.
- **3c — music.**
  - The RapidAPI key and the flashapi client with a quota ledger, manual refresh only.
  - The track store, and the peak-safe audio chain.
  - The Settings «Музыка» card.
- **3d — the Montage screen (the timeline editor)**, built from the Stage 3 artboards in the
  Claude Design canvas.
  - Drafts, the timeline, the preview, the properties and media panels.
  - Rendering and the render queue.
- **3e — videos and photo usage.**
  - The Photos «Видео» tab.
  - The «Неиспользованные» and «Отклонённые» filters, reject and restore.
  - The counts, the «файл удалён» state, «Новый монтаж», and the export folder settings
    (moving it).
- **3f — own uploads («Мои»).**
  - Own photos, own videos (MP4/MOV; trim, rotation, HDR/VFR normalisation), own music and own
    stickers.
  - All of them come through main's file dialog.

Order:

- **Then:** 3b and 3c.2–3c.4 alongside 3a's second half. After 3a.5: 3b.6 and 3c.5.

## Money and quota model

**Money:** unchanged from Stage 2, and not touched by Stage 3.

**The flashapi quota ledger** (`userData/music-quota.jsonl`) is append-only and fsynced after
each append.

Lines:
- `send { requestId, at }` is written **before** the request leaves.
- `result { requestId, status, remaining, limit, headerNames, at }` follows it.

Rules:
- Every `send` counts, whether its request succeeded or not. So does a `send` with no
  `result` after a crash.
- A torn last line counts as a `send`. The rule is conservative; the next append repairs the
  file.
- Only a user click sends a request. There is one refresh at a time and never a retry.

## Montage as data — `MontageSpec` v1 (the sketch for 3a.1)

```
MontageSpec {
  schemaVersion: 1
  avatarId: Id
  clips:  Clip[]     // 1..20, played back to back; Σ durationMs ∈ 4000..15000
  layers: Layer[]    // 0..20 (≤ 10 text, ≤ 10 sticker); array order = z-order, later on top
  music:  null
        | { source: "trending", trackId: Id, startMs: int ≥ 0 }
        | { source: "own", mediaId: Id, startMs: int ≥ 0 }            // 3f
  seed:   uint32     // pan direction, Ken Burns in/out: variety for the autopilot
}

Clip = { clipId: Id, durationMs: 500..15000 (multiple of 100), transitionIn: "cut" } & one of:
  { kind: "photo",   cell: Cell, motion: Motion }
  { kind: "collage", layout: "collage2" | "collage3" | "collage4",
                     cells: Cell[] (exactly 2 / 3 / 4), motion: Motion, stagger: boolean }
  { kind: "video",   mediaId: Id, trimStartMs: int ≥ 0, focus: Focus | null }   // own upload, 3f; static

Cell   = { photo: { source: "scene", photoId: Id } | { source: "own", mediaId: Id },   // own: 3f
           focus: Focus | null }          // null only from headless callers; drafts always store it
Focus  = { x: 0..1, y: 0..1 }
Motion = "kenburns" | "pan" | "static"

Layer = { layerId: Id, startMs, endMs }   // multiples of 100; 0 ≤ start < end ≤ total; end − start ≥ 300
  & one of:
  { kind: "text",    value: Caption, font: "manrope" | "playfair" | "oswald" | "ptmono" | "caveat",
                     style: "none" | "plaque" | "outline", x: 0..1, y: 0..1 (box centre), scale: 0.5..2 }
  { kind: "sticker", sticker: { source: "builtin", stickerId: Id } | { source: "own", mediaId: Id },
                     x: 0..1, y: 0..1 (centre), size: 0.05..0.6 (of frame width) }
```

Rules beyond the shape:
- A scene photo appears at most once per montage.
- `transitionIn` has one value today, `"cut"`. Stage 3 uses hard cuts only (V1). A crossfade
  can be added later without breaking the schema.
- **Drafts vs renderable specs** (2026-09-29, «Новый монтаж»):
  - A saved draft (`MontageDraft`) has the same shape, but it may be incomplete: `clips` is
    0..20, and the 4–15 s total is not yet enforced.
  - Only `videos.render` requires a complete `MontageSpec`.
  - The editor's «Рендер» stays disabled, with its reasons shown, until the draft is complete.
- The engine adds a **resolved** part, stored only in the video record:
  - the focus values filled in;
  - each text layer's `{ lines, sizePx, box }`;
  - each clip's frame range;
  - the music's `{ startMs, gainDb, trackSha }`;
  - the sha256 of every input file.

`defaultSpec(avatarId, photoIds, seed)` (3a.3, done) is shared by «Монтаж из выбранных · N»,
«Новый монтаж» and the autopilot. Its clip ids are `clip-NNN`, and every focus starts `null`
(`montages.create` fills it through `focusFor`):

| Photos selected | Default montage |
| --- | --- |
| 0 | an **empty draft** for the avatar: no clips, no layers, no music. This is «Новый монтаж» on the «Видео» tab (the owner's option Б). It is not renderable until clips are added. |
| 1 | one photo clip, 8.0 s, Ken Burns |
| 2–4 | one collage clip of that size, 8.0 s, Ken Burns, stagger on |
| 5 ≤ N ≤ 20 | N photo clips, Ken Burns, over `clamp(N × 1300, 4000, 15000)` ms divided by `splitEvenly` (the old «Слайды»). 20 photos give 15.0 s = 10 × 800 ms + 10 × 700 ms: 0.75 s each is off the 100 ms grid. |
| N > 20, a duplicate id, or a bad seed | refused. `photoIds` is capped at 20 in the contract, the same as the clip cap. The UI disables «Монтаж из выбранных» above 20 and says why (backlog 7). |

Validation has two halves:
- **Structural** (Zod, shared): shape, bounds and the caption rules.
- **Referential** (engine):
  - scene photos are eligible (the rule above);
  - own media exists and has the right kind;
  - the track is cached and at least `startMs + total` long;
  - stickers exist;
  - fonts cover the text (statically guaranteed, N17).

`defaultSpec`'s three shapes. Its «фото на видео» numbers are 1 / 3 / 5.

```
<exportRoot>/<SafeName>/<YYYY-MM-DD>_<kind>_<NNN>.mp4   the ONLY copy of each video
<exportRoot>/<SafeName>/.studio-part-<jobId>.mp4        the final encode in progress (same directory)
userData/render-tmp/<jobId>/                 clip intermediates (CRF 8), text PNGs, concat list: local volume
userData/render-tmp/text/<previewId>.png     text previews for the editor (short-lived)
userData/music/{lists,tracks,covers}/        userData/music-quota.jsonl
userData/secrets-rapidapi.bin                a second KeyStore (S20)
app assets: studio/assets/fonts/ (5 TTF + emoji font + OFL + manifest),
            studio/assets/stickers/ (generated APNGs + catalog.json + the generator script's output hash)
```

The library survey (S17) reads only the records and the pending intents at open. It checks a
record's file lazily, with a `stat` when a list is shown. It verifies the sha256 lazily too,
on playback, on reveal, or on an explicit check.

A record's `fileState`, derived on read and never stored:
- `present`: the root matches and the size matches;
- `missing`: the root matches but there is no file → «файл удалён»;
- `changed`: the size or sha256 differs → «файл изменён вне Studio»; playable, and still used;
- `elsewhere`: the record's `rootId` is not the current export root → «файл в другой папке».

Every state keeps the photos used. A `missing`, `changed` or `elsewhere` record offers
«Удалить запись».

## Invariants (tests must pin each; numbering continues Stage 2's 1–13)

14. **Metadata allowlist** — as the Metadata row states, checked before commit. Tests render
    from EXIF-, XMP- and C2PA-laden photo fixtures and from an audio file carrying
    title/artist tags. They assert the allowlist exactly, with ffprobe and with the box walker.
15. **No network in render.**
    - Every ffmpeg input is a local path under the library, `userData/music`,
      `userData/render-tmp/<jobId>` or the app assets, and carries
      `-protocol_whitelist file`. The concat list
      holds only the job's fixed relative names.
    - A static test finds no fetch or network import in the render modules.
16. **No text or path in `-filter_complex`.** The graph string uses a strict charset: numbers,
    filter names, labels, fixed option names. A property test covers random valid specs.
17. **SVG text is inert** (A3, SP2).
    - Text enters the fixed SVG template only as XML-escaped character data.
    - **The only `href`s are `data:image/png` URIs the engine builds from the bundled emoji
      font**, looked up by the CBDT reader from a sequence already accepted by the caption
      rules. No `href` is ever derived from user text. resvg 2.6.2 resolves nothing but
      `data:` URIs, and there is no resources dir.
    - Any resvg error is a hard failure, never a fallback.
    - Tests:
      - SP2's 48 checks become a property test. `<`, `>`, `&`, `"`, `'`, `&lt;`, `]]>`,
        `<!--`, `<?xml` and a hostile caption with `</text><rect …/><image
        href="file:///…"/>` render as glyphs, leaving exactly the template's own
        elements;
      - a control character is refused before layout.
18. **Only eligible scene photos.** Each of the following is refused with
    `PHOTO_UNAVAILABLE` before ffmpeg starts: a candidate, the master, an imported avatar's
    photo, an age-failed candidate, a rejected photo, another avatar's photo, a missing
    photo. The same single function answers `photos.list`, the bin, the counts and
    `eligibleUnusedPhotos` (A1).
19. **Caption rules.** Charset (with emoji coverage from the CBDT reader's `has()`), no
    control characters, length, lines, youth words and emoji, and the number table, at both
    the contract and the engine. Each of these is refused with its Russian message, never
    dropped or drawn as tofu: Cyrillic, U+0001, an emoji missing from the font, a youth
    emoji, "teen".
20. **Exact A/V length** (S6).
    - **Video:** exactly `Σ durationMs × 3 / 100` frames.
    - **Audio:** built in-graph with `apad,atrim=end_sample=Σ durationMs × 48`. Its duration is
      ≤ the video's and ≥ the video's minus one AAC frame (21.3 ms).
    - **Never** use `-frames:v`, `-t` or `-shortest` as the terminator.
    - With no music, the track is silent.
21. **Audio peak safety** (A5): the output's true peak is ≤ −1 dBTP, and the applied gain is
    never above 0 dB. Tests cover three fixtures (backlog 9, SP5):
    - **hot:** the hottest cached track, `4199287736976977` at TP **+3.0 dBTP**, which needs
      −4.5 dB. It replaces the earlier +0.4 fixture;
    - **threshold:** a track at TP −1.6, right at the −1.5 target;
    - **quiet:** a track at TP −5.2 or lower.

    Each is measured on its clip segment, not on the whole track. The critic's probe
    measured the AAC-LC 192k re-encode overshoot at ≤ 0.1 dB.
22. **Fonts.** Text renders only with the bundled font files, their sha256 pinned:
    the five text statics and `NotoColorEmoji.ttf` CBDT v2.051.
    - A static test proves that each text TTF's cmap covers the allowed non-emoji charset
      (N17).
    - A **property test runs the CBDT reader over the full Unicode `emoji-test.txt`**.
      Every fully-qualified sequence the font claims maps to exactly one bitmap, and every
      other sequence is refused. SP2's GSUB pass was simplified, so this test is its real
      proof.
    - No system fonts, no fontconfig (`fontBuffers` only).
23. **Video write order** (the Commit row): the file first, then the record.
    - **Invisible until done:** a finished name in the export folder never holds a partial
      file, only an empty placeholder until the rename. The record is write-once and is
      committed only after the file is renamed, verified, and its directory fsynced.
    - **Settled on open** (the Commit row's crash windows):
      - `.studio-part-*` temps are swept;
      - 0-byte placeholders named by our pattern, with no intent, are deleted;
      - an intent whose file matches its size and sha256 is adopted as the record;
      - any other intent is dropped;
      - `userData/render-tmp/*` is swept.
    - **Hands off the owner's files:** Studio never deletes any other file in the export
      folder.
    - **Locked files:** the sweep **tolerates EBUSY and EPERM** (a file still held by an
      orphaned ffmpeg). It skips the file, retries on the next start, and never fails the
      library open (S5).
    - **Tests:** a kill at each crash window, and a record whose file is gone (→ `missing`).
24. **"Used" is derived from the records** (A2), never from the files.
    - Deleting a video in Studio deletes the file (if present) and the record, and so frees
      its photos. The owner deleting the file outside Studio keeps them used until «Удалить
      запись».
    - Photos named by queued or running render specs are never returned by
      `eligibleUnusedPhotos` (S16). The library takes an injected reserved-set provider in
      3a.2. The two-queued-specs test runs in 3a.6, where the queue exists (backlog 4).
    - Own media never appear in used or unused counts.
25. **Bounded renders and a real queue** (S10).
    - Queued jobs appear in `Snapshot.jobs`, can be cancelled, and count toward `IN_FLIGHT`.
      A library switch is refused while any render is queued or running.
    - Every render has a timeout. A cancel or timeout kills ffmpeg and removes its temp
      file. No placeholder, record or used mark is left behind.
26. **Stage 3 spends nothing.** The modules under `studio/engine/montage/**`, `render/**`,
    `music/**` and `media/**` never import `openrouter` or `money`: a static test.
27. **Headless.** `videos.render {spec}` works with no window. The packaged E2E drives it over
    the control channel.
28. **The media protocol, widened** (S2).
    - **Routes:** `video/<avatarId>/<videoId>`, `track/<trackId>`, `cover/<trackId>`,
      `sticker/<stickerId>`, `text/<previewId>`, `media/<mediaId>`. The `photo` route stays.
    - **Checks on every route:** id-only, naming convention, `realpath` inside its own root, a
      MIME allowlist, HTTP Range.
    - **The `video` route** resolves through the record: its `rootId` must equal the current
      export root's, and `<exportRoot>/<relPath>` must `realpath` inside the export root.
      Anything else is a 404. A `relPath` holding `..`, an absolute path, or a symlink out of
      the root is refused.
    - **Scheme and CSP:** the scheme is registered with `stream: true`; the CSP adds
      `media-src studio-media:`.
29. **The music key and child envs.** The RapidAPI key lives only in its `KeyStore`
    (`safeStorage`, main) and the engine's memory: never in the renderer, logs, library,
    cache files or quota lines. The flashapi client takes the key and the base URL as
    parameters, and tests never pass a real key. Every ffmpeg child's env keys are a subset
    of the engine env allowlist (S4).
30. **Quota.**
    - A `send` line is on disk before the request leaves.
    - The 31-day window, the `remaining = 0` floor, no retry and no overlap all hold.
    - Tests: a crash between `send` and `result`, a torn last line, and the boundary: with 29
      sends in the window a request leaves; with 30 it is refused.
31. **Downloads.**
    - **Sources:** `https` only, port 443, from hosts matching one of two anchored,
      lowercase **patterns** (SP5; the concrete host depends on where the request comes
      from, e.g. `fra` or `fkiv` edges):
      - `^scontent-[a-z0-9]+-[0-9]+\.cdninstagram\.com$`;
      - `^instagram\.[a-z0-9]+-[0-9]+\.fna\.fbcdn\.net$`.
    - **Matching:** exact, at label boundaries: never `endsWith("cdninstagram.com")`
      without the dot. There is no redirect to another host. Covers use the same hosts.
      Anything else is refused and logged by host only.
    - **Size caps:** 25 MB per track, 2 MB per cover.
    - **Acceptance:** a track is accepted only after the box walker reads an `mp4a` stream
      (HE-AAC `mp4a.40.5` and AAC-LC both accepted) and a bounded decode proves it is audio
      of about `duration_in_ms`. Its sha256 is recorded.
    - **Expiry:** downloads run at refresh time, and no URL is used past its `expiresAt`
      (≤ 104 h after the response).
    - **Test overrides:** the E2E-only mock-CDN host override and the base-URL override are
      both compiled out of packaged production builds (invariant 13 extended, S11).
32. **Unsupported until landed** (N9). A spec using layers, music or own media before its
    slice ships is refused with `MONTAGE_INVALID` "not yet supported", never dropped.
33. **Unique export names** under parallel renders: the placeholder is claimed with an
    exclusive create, and a collision moves to the next NNN. Two concurrent commits never
    share a name, and a rename only ever replaces its own placeholder (S15). A file the owner
    put there is never overwritten.
34. **Own uploads come in through main only.** The renderer never sends a path or bytes: the
    T6c rule. The path comes only from main's own native dialog, over the control channel.
    Unlike T6c, which passed bytes, the engine now opens a user-picked path, because 2 GB
    videos cannot travel as bytes. So the handoff is spelled out (backlog 10):
    - an `lstat` check that it is a **regular file**;
    - **no symlink following**: a symlink, a directory or a device is refused, and the file
      is opened with `O_NOFOLLOW` where the platform has it;
    - a **byte-capped** copy into staging that stops at the kind's cap even if the file
      grows during the copy;
    - validation and normalisation before anything else reads it.

    The imported file keeps none of its source metadata.
35. **The export folder is required** (2026-09-29).
    - **Up front:** `videos.render` checks the export root before a job is queued: it exists,
      it is a directory, a probe file can be created and removed there, it carries (or can
      be given) its root marker, and it has free space ≥ 2 × `estimateBytesUpper`. If not, it
      refuses with `EXPORT_UNAVAILABLE` and a reason. The refusal costs nothing: no job, no
      reservation, no intermediate. The UI shows a clear notice pointing to Settings.
    - **At commit:** the root is checked again. If it vanished mid-render (e.g. a drive
      unplugged), the job fails with `EXPORT_UNAVAILABLE`, the temp files are swept, and no
      record or used mark is written.
    - **Tests:** a missing folder, a file in its place, a read-only folder, and removal during
      the render.
36. **Colour and fidelity** (SP1).
    - **Colour:** a chart fixture (a full-range BT.601 JPEG, 24 patches) with a coloured RGBA
      sticker, opaque and at alpha 128, is rendered and decoded without conversion. The
      patch means must be within **2 code values** (Y/Cb/Cr) of the expected limited-range
      BT.709 values, and the opaque sticker's within **1**. SP1 measured 0.96 / 1.60 / 1.54,
      and 0.48 for the sticker. 3a.5's chain (with `accurate_rnd`) measures 0.84 / 0.73 /
      0.85 on macOS arm64 6.0 and 0.56 / 0.89 / 0.89 on Windows x64 6.1.1. Without the
      rounding flags, x86 reached 2.16 in Y, past the bar.
    - **Negative controls:** the same test run on the two known traps must **fail** its
      tolerance. The traps are a sticker left to the auto scaler (14.6 codes off) and a photo
      through a bare `format=yuv420p` (27.6 codes off). This proves the test can catch a
      regression.
    - **Intermediate fidelity:** the final encode from CRF 8 intermediates is within **0.002
      SSIM** of the final from lossless (`-qp 0`) intermediates, both measured against the
      lossless clips (SP1: 0.0009).
    - **Measured by 3a.5**, with the frames aligned by number:
      - lossless 0.99328;
      - CRF 8 0.99251, a loss of **0.00076**;
      - a CRF 30 control scores 0.96353, so the test can fail.
    - It runs in the default suite on real ffmpeg.

**3a.5 — DONE (2026-09-30).** The graph builder (`studio/engine/render/`: `pass1.ts`, `pass2.ts`, `profile.ts`, `filterString.ts`, `zoompan.ts`).
- **Overlays:**
  - A windowed layer is cut to its frames (`trim=end_frame=E−S,settb=1/30,setpts=N+S`) and overlaid with `eof_action=pass`. It **never uses `enable=`**, which was measured to drop a frame.
  - A layer spanning the timeline is not cut and uses `endall`. Its looped input never ends, so the output ends on the main input's last frame.
  - `OverlayInput.animated` became `format: "png" | "apng" | "gif"`.
- **Animations** (APNG/GIF) are read once and looped in the graph (`fps=30,format=rgba,…,loop=loop=-1:size=300`), **never with `-stream_loop` or `-ignore_loop`**. Both were measured: the demuxer's duration is one frame short, so each loop eats a frame, and a file with a finite loop count ends the overlay (and with `endall`, the whole output). A still is converted once and its frame repeated.
- **Inputs** (invariant 15):
  - every input carries `-protocol_whitelist file` plus an **explicit demuxer**: `-f image2 -pattern_type none` for a photo or PNG, `-f apng`, `-f gif`;
  - photos also carry **`-noautorotate`**, and `PhotoSource` sizes are the **STORED** sizes (as jsquash, the sidecar and the focus frame see them), so the pixels ffmpeg delivers match the geometry.
- **Filter graph** (invariant 16):
  - `assertSafeFilterGraph` enforces a strict charset and a **filter-name allowlist** (`scale`, `format`, `setparams`, `crop`, `loop`, `settb`, `setpts`, `zoompan`, `fade`, `color`, `overlay`, `setsar`, `trim`, `fps`, `anullsrc`, `apad`, `atrim`). Nothing that can read a file (`movie`, `drawtext` with `textfile`, `lut3d`, `subtitles`, …) is allowed;
  - a quote is accepted **only** as the quoting of an option value, built by `quoteExpression` from the expression charset;
  - a `/` appears only inside a quoted expression or a `settb=1/N` time base.
- **Refusals:**
  - a clip under `MIN_CLIP_MS` (500 ms), or of a length that is not a whole number of frames, → `BAD_DURATION`; a `RangeError` from the shared timing is wrapped, never leaked;
  - a photo with an impossible size → `BAD_PHOTO_SIZE`.
- **Colour:** the photo chain gained `flags=accurate_rnd+full_chroma_int`. Without it, x86 6.1.1 drifted to Y 2.16. With it: macOS 0.84 / 0.73 / 0.85, Windows 0.56 / 0.89 / 0.89 (the Output format row, invariant 36).
- **Zoompan parity:**
  - ffmpeg's size truncation and even snapping put the real crop window up to **1.26 canvas px (≈ 0.5 output px)** from the shared `motionWindow`;
  - `motionWindow` is **left unchanged, by design**; the builder models ffmpeg's arithmetic instead;
  - real frames match the explicit ffmpeg model with a median error of 0.08, worst 0.23 (0.28 on Windows), against a 0.4 tolerance.
- **Fidelity** (invariant 36): with the frames aligned by number, the final from CRF 8 intermediates loses **0.00076 SSIM** against the final from lossless ones (bar 0.002). The CRF 30 control scores 0.96353, so the test can fail.
- **Metadata:** `creation_time` is **0** in `mvhd`, `tkhd` and `mdhd` on macOS 6.0; Windows is recorded in 3a.9. Windows' ffprobe 4.4 omits `vendor_id`, so the tests read the vendor from `stsd` directly.
- **Tests:** the real-ffmpeg tests run **in the default suite**, because they are the only proof of invariants 20 and 36. CI passes on **Windows 6.1.1** and **macOS 6.0**.

**3a.6 — DONE (2026-09-30).** The render queue and runner (`studio/engine/renderQueue/`: `pool.ts`, `progress.ts`, `queue.ts`, `runner.ts`, `sweep.ts`; `studio/node/runFfmpeg.ts`'s `runFfmpegArgv`).
- **The pool** (`renderPoolSize`): «Авто» = `min(clamp(floor((cores − 1) / 2), 1, 4), max(1, floor(0.25 × totalmem / PEAK_RSS_BYTES)))`, with `PEAK_RSS_BYTES` = 768 MiB and `os.totalmem()`, never `freemem()`. A tiny machine still gets 1.

The split was chosen from time on one 2-clip timeline with no overlays, so 3b must not rely on it. The fold never goes back, and it **caps at F − 1** until the job's own end (verify and commit); then the registry sets `done = total`.
- **One deadline per job:** `renderTimeoutMs` = `max(90 s, 30 × the video's seconds)`, shared by every ffmpeg call of the job. Each call gets what is left, and a timeout is reported against the whole budget.

- **Cancel is render-only both ways:** `videos.cancel` / `RenderQueue.cancel` refuses a job that is not a render, and `avatars.cancel` answers `NOT_FOUND` for a render job.
- **Output guard:** the runner writes and, on failure, removes only a file named `.studio-part-<jobId>.mp4`. It checks the job id and that name before anything is built.
- **Stderr scrubbing:** an ffmpeg error or timeout that may reach the UI has the temp root and the export folder replaced by `<tmp>` and `<export>`, in both separator spellings. The gaps the round-2 re-review found are in 3a.8b's MUST list, under "errors reach the UI".

**3a.7 — DONE (2026-09-30).** The output verifier (`studio/engine/verify/`, `verifyRenderedMp4`).
- **API:** `verifyRenderedMp4(path, {frames, forbiddenStrings}, {maxBytes = 64 MiB})` → `{ok: true}` or `{ok: false, reasons: [{code, message, path}]}`. There are **36 reason codes** (`VERIFY_REASON_CODES` in `types.ts`); callers branch on `code`, and `message` is for the log only. I/O errors throw `VerifyIoError`.
- **The final allowlist**, strict everywhere:
  - **top level:** `ftyp`, `moov`, `free`, `mdat`;
  - **`moov`:** `mvhd`, `trak` (repeatable), `udta` (`meta` → `hdlr`, `ilst` → `©too` only);

- **The delta from the first draft:** `sdtp`, `cslg`, `stps`, `co64`, `fiel` and `clap` were removed, since ffmpeg never writes them. `stbl` and `dinf` are no longer tolerant of unknown boxes. 3a.9 adds back, pinned, whatever Windows 6.1.1 writes.
- **Duplicates:** each box type appears at most once per parent, except `trak` in `moov`, `avc1`/`mp4a` in `stsd` and `url ` in `dref`. Anything else is `DUPLICATE_BOX`.
- **Exact leaf pins:**
  - every fixed field and every leaf size is pinned to what ffmpeg writes: `mvhd`/`tkhd` reserved fields, `hdlr` names (`VideoHandler`, `SoundHandler`), a single self-contained `url `, `avcC` to the byte, `©too` = one `data` box holding `Lavf<version>`;
  - `sgpd` is **26 bytes** (the AAC roll group, roll −1);
  - `sbgp` is **28 bytes**, with its `sample_count` still free (backlog);
  - `ftyp`: major brand `isom`, compatible brands ⊆ {`isom`, `iso2`, `avc1`, `mp41`};
  - the compressor name matches `^Lavc\d+\.\d+\.\d+ libx264$`.
- **Text:** `TEXT_IN_INDEX` fires on any run of **≥ 16 printable bytes** in `moov` (`PRINTABLE_RUN_MIN`) other than the pinned compressor name.
- **Media data:** `MEDIA_DATA_MISMATCH` fires unless the tracks' chunks tile `mdat` exactly: no gap, no overlap, no offset outside it, and nothing undescribed at its end.
- **Tolerances:**
  - **audio:** ∈ [video − 23 ms, video + 1 ms] (`AUDIO_UNDER_MS`, `AUDIO_OVER_MS`);
  - **movie and video:** ±2 ms of the expected;
  - **`stsz`:** the sample count is exact (`FRAME_COUNT_MISMATCH`).
- **Content scan:** a streaming scan of the whole file (`mdat` included) for XMP, Exif, C2PA and ICC markers, and for the caller's `forbiddenStrings` (a source's Artist/Copyright). Each is searched as UTF-8 and as UTF-16LE/BE, and must be at least 6 bytes in UTF-8 (`MIN_FORBIDDEN_STRING_BYTES`).
- **Masking and escaping:** a caller's string is **masked** in every reason message (in its UTF-8, Latin-1 and UTF-16LE/BE forms), so the log never repeats it. Every message and path is escaped to printable ASCII, and a quoted value is cut at 32 characters.
- **A second opinion:** `checkEngineLayout` runs the uniquifier's `findMovSignatureFields` (imported read-only) on `ftyp` + `moov`, as N10 asks.
