## 0. The plan in short

1. **Order:** 5a.0 (descriptor) → 5a.1a (phone-look text) → canary C1 → 5a.1c (body traits) → canary C2 → 5b.1
   «Оживить» → 5a.2 (scene system **with the code template**) → 5a.3 («Смелая») → 5b.2 (batch clips). This is the
   concept's order (Q1: «главное чтобы в правильном порядке»).
2. **5a.0** fixes the biggest identity lever, the descriptor.
   - The import prompt gets a hair rule.
   - A paid descriptor-vs-master check runs automatically at import and at creation (the owner's answer), and on
     demand as «Проверить описание».
   - A free `avatars.editDescriptor` writes the owner's accepted text.
   - The 6-value `HairColor` enum stays as it is.
3. **5a.1a** changes text only: capture lines first; only the mirror shows a phone; «Only she is in focus» goes; a
   positive artefact line; light named by its source; one seeded imperfection and a tidiness draw; «Реализм камеры»
   kept and fixed. The binding asks for «the exact hair colour from the reference photo», and the writers never
   describe her hair. The pools move to ordinary places with no paper or screens, and phone activities never land on
   a selfie or mirror slot. Everything lives in one new module, `scenes/phoneLook.ts`. There is no contract field and
   no money change.
4. **5a.1c** adds body traits: height, bust, figure (six types), legs (length and shape), «Попа» (size and shape), and
   up to two body marks.
   - All are optional, stored as flat trait keys.
   - Code renders them into a body phrase carried by the prompt descriptor; the LLM never writes it.
   - They are set in the wizard's «Тело» tab and on the avatar's new «Внешность» tab. Import proposes what the photo
     shows, and the owner saves it.
   - Existing avatars stay unchanged until he sets them.
5. **His model stays `grok-imagine-image-quality`** (Q16). Its author drift is fixed in text and measured by C1.
6. **5b.1 «Оживить»** (size L): Kling 3.0 std, 5 s, with the slow prompt. Its money rules:
   - write the journal before the submit, and never resubmit;
   - reserve the requested length + 1 s;
   - a billed failure settles from `/generation?id=`;
   - a 20-minute job lifetime;
   - after a restart, reconcile instead of adopt.
7. **Paid steps:** canaries C1–C3 (§13), each with the owner's explicit OK. The balance is about $1.13, so C1 needs a
   top-up first (Q6).
8. **Owner questions for the first slices:** Q6 (the top-up), Q14 (the Fitness reword, tested in C1), Q5 (only the
   «Фотосессия на телефон» label), and the mockup's open items D2–D4 (§15; D1 decided in r2.1).

### 5.3 The descriptor-vs-master check (S5.0c)

**What it does:** one vision call. Its input is the master plus the stored descriptor (and, from 5a.1c, the body

**Aspects** (the mockup's «Сверка с фото», 09–11):

| Aspect | Covers | States |
|---|---|---|

**Answer (strict JSON):**

```
{
  aspects: {
    <aspect>: {
      state,
      descriptor?: "<≤ 40 chars, Russian>",
      photo?: "<≤ 40 chars, Russian>"
    }
  },
  descriptor: "<corrected English text, or the same text>"
}
```

The short Russian phrases are the mockup's «В описании: волнистые блонд · На фото: прямые платиновые с чёлкой». They
are model output, so the reader parses them with Zod, caps them at 40 chars, applies `NO_HIDDEN_CHARS`, and the UI
renders them as plain text.

**The reader** (`avatars/descriptorCheck.ts`, new, pure):
- It tolerates a fence and drops unknown aspects. `matches` means no `mismatch`.
- **The proposal:**
  - it is folded by `normaliseDescriptorText`, then checked against `AvatarDescriptor` at her age, together with her
    body phrase;
  - it must not **add** a body word (r2.1 · N2). The filter is a token diff: lower-cased word tokens of the proposal
    minus those of the stored text, checked against height, tall, bust, figure, hips, legs, bottom, waist. Model-written
    descriptors name the build freely (a stored «a curvy figure» is kept), so a presence test would null every
    proposal for them;
  - it is `null` when it fails, equals the stored text, or there is no mismatch.
- **A `body` mismatch never yields a text fix.** The UI routes it to «Тело» («Изменить тело»), because the phrase
  comes from the traits (m7).

**Money and ids (I5.9, m7):**

**When it runs:**
