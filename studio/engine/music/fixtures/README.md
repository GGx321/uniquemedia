# Music fixtures (Stage 3c.1)

Test inputs for the music tasks 3c.3 (flashapi client), 3c.4 (track store) and 3c.5 (audio
chain). They are pinned by size and sha256 in `index.ts` and verified by `fixtures.test.ts`.
Import the paths from `index.ts`; do not hard-code them.

## Licensing

The repository is PUBLIC, so no third-party recording lives here. The track files in `tracks/` are
SYNTHETIC: generated by `generate.ts` from sine tones, pink noise and short sine bursts, with
nothing downloaded and nothing sampled from any song. Earlier commits held excerpts of commercial
tracks; they were replaced and removed from the tree (history is a separate decision of the
owner). Never add a recording of real music to this folder; extend `generate.ts` instead.

The list JSON carries public track metadata (titles, artists, cover URLs) captured from the API,
for the client and store tests.

## Lists (`lists/`)

Two responses of the flashapi trending endpoint, byte-for-byte as captured, except that
`response.alacorn_session_id` is replaced with `"REDACTED"`. Neither response carries the
RapidAPI key (the key travels in a request header, which was never stored); the test greps
for it anyway.

**The signed CDN URLs (`oh=`, `oe=`) are left in.** They expired about 104 to 108 hours
after the capture (2026-09-27), so they grant nothing. The `_nc_gid` parameter in them is a CDN session id of flashapi's requester, not the owner's,
and it expired with the URLs. The `oe=` values are still useful as
real-world input for the expiry parser.

## Tracks (`tracks/`)

HE-AAC (`mp4a.40.5`) stereo in MP4, the profile the API delivers, re-wrapped with `-c copy` and no
metadata (only the container brands remain, no `encoder` tag, the output is bit-exact). Each file
is a quiet bed (tones and pink noise) with a 5 ms burst every two seconds from
3 s on; `generate.ts` searches for the burst level at which the DECODED file's true peak, as
`ebur128=peak=true` prints it, is exactly the value below. Peak and loudness are independent by
design: the hot file peaks at +3.0 dBTP and is still far under the -12 LUFS the tests expect.
The bursts all sit inside the segments the render tests cut (2 s to 8 s, and 0 s to 6 s), because
invariant 21 measures the clip segment, not the whole track.

| File | Stands in for list track | Length | True peak | Purpose |
| --- | --- | --- | --- | --- |
| `hot.mp4` | 4199287736976977 | 8.03 s, 44.1 kHz | +3.0 dBTP | invariant 21 hot: needs -4.5 dB |
| `threshold.mp4` | 774126508789756 | 8.03 s, 44.1 kHz | -1.6 dBTP | invariant 21 threshold: right at the -1.5 target, gain 0 |
| `quiet.mp4` | 4207179866261956 | 8.03 s, 44.1 kHz | -5.7 dBTP | invariant 21 quiet: at most -5.2, gain 0 |
| `he-aac-48k.mp4` | 1644648520025224 | 6.02 s, 48 kHz | -5.5 dBTP | the 48 kHz input variant (the rest are 44.1 kHz) |

The track ids are list entries the fake CDN serves these bytes for; the audio itself has no
relation to those tracks. Lengths are as ffmpeg reports them (AAC frames are 46 ms, so the index
claims the nearest 10 ms).

### Regenerating

`bun studio/engine/music/fixtures/generate.ts` (macOS only: Apple's `afconvert` is the HE-AAC
encoder, because ffmpeg's own AAC encoder writes AAC-LC and the bundled build has no
`libfdk_aac`; the committed files are what the tests read, so CI never needs it). The output is
deterministic for one macOS and ffmpeg build. After a regeneration, update `bytes` and `sha256` in
`index.ts` from the script's output and say why in the commit.

Not here: the audio file that carries title and artist tags (invariant 14). The API tracks
have no tags, so 3c.5 makes that file itself, at test time, from the hot track (`../testing/taggedTrack.ts`).
